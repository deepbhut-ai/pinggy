Getting Started

Pinggy Documentation

Learn how to expose local servers to the internet instantly with secure SSH reverse tunnels. No downloads, no installation, no credit card required.

  • Public HTTPS URLs for localhost in one command
  • End-to-end encryption over SSH
  • Custom domains, password protection, and request inspection
Tip: If you already have an SSH client installed, you can start tunneling immediately. Otherwise use the dashboard to create and manage tunnels.

Quickstart

The fastest way to expose a local service is with the SSH command below. Replace 8080 with the port your app is running on.

Terminal
ssh -p 2222 -R0:localhost:8080 tunnel@pinggy.local
==> public URL: https://a1b2c3d4.pinggy.local
==> forwarding: 0 -> localhost:8080

Step 1

Start your local application on any port, e.g. http://localhost:8080.

Step 2

Run the SSH command above and copy the public URL that appears.

Free users: Public URLs are temporary for the session. Upgrade to keep persistent domains and custom subdomains.

CLI Usage

Pinggy uses the SSH protocol directly, so any standard SSH client works. The command format is:

ssh -p <server_port> -R0:localhost:<local_port> <user>@<host>

Common options

  • -p 2222 — connect to the Pinggy tunnel server port
  • -R0:localhost:8080 — request a remote forward from any available remote port to local port 8080
  • -o ServerAliveInterval=30 — keep the connection alive behind NAT/firewalls

Example with keepalive

Terminal
ssh -p 2222 -o ServerAliveInterval=30 -R0:localhost:3000 tunnel@pinggy.local

Create a Tunnel

Tunnels map a public URL to a service running on your machine. You can create and manage tunnels from the dashboard or via the CLI.

Using the dashboard

  1. Log in to your account at /login.
  2. Go to the dashboard and click Create Tunnel.
  3. Enter the local port and choose a domain option.
  4. Copy the generated SSH command or token.

Using an access token

For authenticated users, tokens can be used to pre-configure tunnels and enable persistent domains.

ssh -p 2222 -R0:localhost:8080 <token>@pinggy.local

Custom Domains

Paid plans allow you to attach your own domain or request a fixed Pinggy subdomain.

  • Bring your own domain and point a CNAME to your tunnel target
  • Reserve a fixed subdomain so URLs stay the same across sessions
  • Automatic HTTPS certificates managed by Pinggy
Setup: Add your domain in the dashboard under Domains, then configure the DNS CNAME record shown.

Access Control

Protect your public tunnels with password authentication or IP allow-lists.

Password protection

Enable basic authentication from the dashboard to require a username and password before requests reach your local app.

IP allow-list

Restrict access to specific IP addresses or ranges for additional security. This is available on Pro and Business plans.

QR Code Sharing

Every tunnel URL can be displayed as a QR code for easy mobile testing. Scan the code to open your local app directly on a phone or tablet.

Use case: Test responsive designs, mobile APIs, or share a preview with teammates without typing long URLs.

Commands

Reference list of useful SSH flags and patterns.

Forward HTTP

ssh -p 2222 -R0:localhost:8080 tunnel@pinggy.local

Forward TCP

ssh -p 2222 -R0:localhost:5432 tunnel@pinggy.local

Keep alive

-o ServerAliveInterval=30 -o ServerAliveCountMax=3

Custom subdomain

ssh -p 2222 -R myapp:80:localhost:8080 tunnel@pinggy.local

Configuration

Save commonly used settings in your SSH config file at ~/.ssh/config:

~/.ssh/config
# Pinggy tunnel host
Host pinggy
  HostName pinggy.local
  Port 2222
  User tunnel
  ServerAliveInterval 30
  ServerAliveCountMax 3

After saving, you can simply run:

ssh -R0:localhost:8080 pinggy

Troubleshooting

Connection refused

Verify that the tunnel server is reachable on port 2222 and that your local service is actually listening on the port you forwarded.

URL not loading

Make sure your local app binds to localhost or 0.0.0.0. Binding to a specific LAN IP can prevent the tunnel from reaching it.

Session disconnects

Add keepalive options to your SSH command or config so idle connections are not dropped by routers or firewalls.

Permission denied

Check that you are using a valid token or username. Tokens can be regenerated from the dashboard if needed.
