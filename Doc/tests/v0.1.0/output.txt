# Local run verification — 2026-08-29 (VS Code integrated browser)

## Goal
Run the IRAGT "pinggy" tunnel-service project locally inside the VS Code integrated browser.

## Environment fixes required
1. `.venv` shipped in the project copy was built on LINUX (ELF x86-64 binaries,
   `home = /usr/bin` in pyvenv.cfg) — project was copied from prod server `/opt/pinggy`.
   Executing it on macOS failed with `zsh: permission denied`.
   Fix: rebuilt with `python3 -m venv .venv --clear` + `pip install -r requirements.txt`
   (Python 3.10.0, macOS framework build). All deps import OK.
2. Port 8000 (node PID 48594), 8010 (python PID 48840) and 8030 were already in use
   on this machine → app started with `APP_PORT=8020` env override.
3. Local PostgreSQL (brew postgresql@14) already accepts `postgres:root@localhost:5432`
   → `.env` DB credentials worked unchanged. Redis on 6379 was already running.

## Notes / caveats
- `.env` is the PRODUCTION config (APP_ENV=production, TUNNEL_DOMAIN=iraglobaltech.com,
  fake payment keys sk_test_xxx / PayPal xxx with *_ENABLED=true). Tunnels created
  locally would advertise *.iraglobaltech.com URLs that only resolve on the prod server.
- `GET /api/v1/users/me` does NOT exist; `/users/{user_id}` treats "me" as a UUID and 500s
  (psycopg InvalidTextRepresentation). Use the real user UUID. Pre-existing API shape,
  not a local-setup issue.
- No code was changed in this run — environment setup only (venv rebuild + local DB).

## Gotchas found & documented
  - E2E test must fetch the tunnel URL from a WORKER THREAD: a blocking urlopen in the
    same event loop as the asyncssh client deadlocks the forwarded channel (timeout).
  - admin.html hardcodes "iraglobaltech.com" strings in System Info (cosmetic; real
    dev domain is localhost:8020).
  - tokens table is empty locally (0006 backfill predates admin seeding) — SSH auth
    falls back to users.tunnel_token (works, verified by E2E).
