# v0.5.0 — Phase D: email system + announcements + password reset — 2026-08-29

Confirmed scope: Job 6 (login email, forgot password, tunnel-stopped, new account,
campaigns) + approved announcements suggestion.

## Changes
1. Migration 0013: `email_logs` (to/subject/kind/status/error), `password_resets`
   (token_hash UNIQUE, expires_at, used_at), `payments.coupon_code` (column the
   v0.4.0 code already wrote defensively).
2. Migration 0014: `announcements` (title/body/level/active).
3. `app/core/email.py`: SMTP via app_settings (smtp_host/port/user/password/from/
   enabled — manageable in ⚙️ Settings), templates (welcome/reset/tunnel_stopped),
   every send logged to email_logs, failures never break requests.
4. auth.py: POST /auth/forgot-password (no account enumeration; mints SHA-256-hashed
   single-use 30-min token; sends reset email) + POST /auth/reset-password
   (single-use enforced, audited).
5. Hooks: welcome email on self-service register; tunnel-stopped email on SSH
   disconnect (ssh_server._cleanup_tunnel).
6. announcements router: CRUD (authed list — users see active only), POST /campaign
   (all|pro|free audiences, 503-gated until SMTP configured, audited),
   GET /announcements/logs, GET /announcements/smtp-status.
7. UI: login.html forgot/reset forms (+ auto-opens via ?reset=TOKEN);
   admin 📣 Announcements page (table + publish form + campaign composer + email
   logs + SMTP status banner); user dashboard announcement banner.
8. **Pre-existing critical bug fixed**: dashboard.html had `let tunnelRateTracker`
   declared TWICE → SyntaxError killed the whole script → the user dashboard page
   NEVER loaded (inherited from the prod-server copy; /admin was unaffected).
   Removed the duplicate — dashboard loads for the first time.
